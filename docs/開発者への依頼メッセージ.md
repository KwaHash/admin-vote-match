### ご依頼：運営サイト admin.seijiselect.jp（運営OS）の本実装

お世話になっております。
運営サイトを、単なる審査一覧ではなく **「運営OS」＝統合キュー型ダッシュボード**として設計しました。本実装をお願いしたくご連絡します。
最重要方針は「**AIは最終承認しない／人は例外・高リスク・要判断だけを確認**」です。

**■ 前提（先にお願い）**
- 本リポジトリ `admin-vote-match` は**まだ GitHub にありません**。`docs/リポジトリ作成依頼.md` の通り、リポジトリ作成と push 受け入れをお願いします（作成後にプロトを push します）。

**■ 対象**
- 仕様書: `docs/実装仕様書_運営admin_運営OS.md`
- 公開質問ボードの正準データ構造: `docs/データ構造_公開質問ボード_共通仕様.md`（国民・政治家と共有）
- 画面: 単一ページ `app/page.tsx`（タブ式の運営OS）。起動 `npm install` → `npx next dev`

**■ MVP（運営OS）**
12メニュー＋9KPI＋AIアシスト。統合キュー（候補者/団体/クラファン/寄付/支出/支援リソース/レポート/質問）をリスク・SLA順に。低リスク=自動承認候補、中=差戻し/要確認、高=法務確認。

**■ 連携（同一Supabase・運営adminが束ねる）**
- 候補者ロスター取込・審査・公開／選挙ページ生成／AI比較文の事前生成 → 国民側「選挙で選ぶ」。
- 課題・政策提言の登録・ファネル段階更新・公開 → 国民側「国と地域の課題」。
- 公開質問の上位選定・送付・回答管理 → 国民側「公開質問ボード」＋政治家側「公開質問への回答」。

**■ 進め方（重要）**
- 画面は完成済みなので**作り直さない**。バックエンドは Supabase、公開は Vercel。
- **AIは承認しない**実装（要約・リスク分類・対応案・差戻し文の生成のみ）。
- **権限**: `admin` / `auditor` / `legal_reviewer` をロールで分離。**監査ログは追記専用**。
- 公開前に**PIIをマスキング**。公開データと内部データを分離。

**■ 今回やらないこと（別フェーズ）**
- 寄付・支出の**実決済**、**実AI（LLM）接続**、政府統計のリアルタイム接続。

まずリポジトリ作成 → プロト push → 仕様書 §「実装順序」のご相談、の順で進めさせてください。よろしくお願いいたします。
